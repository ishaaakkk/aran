# Changelog

All notable changes to Aran are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project follows [Semantic Versioning](https://semver.org/). **Aran is pre-1.0:
breaking changes land in minor releases.**

This file covers the **platform** (the Java modules, `aran-web`, `aran-lake`),
which share one version. The Python SDK versions independently and has its own
changelog in [`aran-client/`](aran-client/).

## [Unreleased]

### Breaking changes

- **Every identifier is renamed to Aran, with no aliases.** Environment variables are `ARAN_*`
  and Spring properties `aran.*`; the Keycloak realm is `aran` (clients `aran-web`,
  `aran-backend`, `aran-cli`); the databases are `aran` and `aran_lake`; schema graphs are
  `urn:aran:*`; response headers are `X-Aran-*`; Java packages are `edu.upc.dtak.aran`, Gradle
  modules `aran-*`, and the Python packages `aran_lake`, `aran_client` and `aran_mcp`.
  *Migration:* rename your environment variables and property keys, and re-create the
  databases, the Keycloak realm and the Fuseki dataset — or start from a fresh install.
- **The `NOSQL_DOCUMENT`, `KEY_VALUE` and `WEB_API` repository types are removed.** They could
  be registered and connection-tested, and no data could ever flow from them. A request naming
  one is refused with a 400, and Flyway `V44` deletes any stored repository of those types
  together with its datasets. *Migration:* export the data to a CSV, JSON or Parquet file and
  upload it, or reach a SaaS API through a Singer tap repository.
- **`SourceConnector` is introspection only.** Its capability half — `accessModes()`,
  `federatedScan()`, `duckDbExtensions()` and `refreshPolicies()` — and `BindingStrategy` are
  deleted: nothing read them. `SourceSchema` is the RDFS graph alone. *Migration:* a connector
  implements `sourceKind()`, `supports()` and `introspect()`, and builds `new SourceSchema(model)`;
  access modes and refresh are decided per repository kind outside the connector.
- **`FILE_SYSTEM` repositories are upload-only.** Aran no longer reads a directory on the
  server for them: scanning one lists nothing, previewing a file by name is refused, and the
  connection test probes nothing. `rootPath` is gone from the repository API (a request that
  still sends it is accepted and the field ignored), and `aran.fs.allowed-roots` /
  `ARAN_FS_ALLOWED_ROOTS` no longer exists. This removes a server-side filesystem read surface.
  *Migration:* upload the file as a dataset of the repository; drop `ARAN_FS_ALLOWED_ROOTS` from
  your deployment.
- **`GET /api/repository-types` no longer returns `connectorAvailable`.** Every repository type
  can take data in, so the flag could only be `true`; each entry is now `{type}`. *Migration:*
  treat every listed type as ingestible.

### Added

- **Concept tooltips in the web UI.** A reusable `InfoTip` component surfaces one-paragraph
  explanations of the platform's load-bearing jargon — bootstrapping, profiling, federation,
  wrappers, denial constraints, alignments, join discovery, schema versions, data products and
  their access modes, OQL — next to the screens that first confront a user with each term. Copy
  lives in one module (`aran-web/src/lib/concepts.ts`) so the same concept reads the same on
  every screen.
- **"Why Aran" documentation page** (`docs-site/docs/overview/why-aran.md`): what Aran adds
  next to a lakehouse or an ETL stack, who it is for, and — explicitly — who it is not for.

- **A performance suite for the query engine** (`aran-operators/query-engine`, package
  `…queryengine.harness`), in two tiers. `PerfGateTest` and `PerfGoldenTest` run on every build
  and assert only machine-independent facts — DDL statement counts, snapshots the resolver is
  asked for, views the emitted SQL names, exact row counts over generated data, and plan-shape
  goldens under `src/test/resources/perf-goldens/`. No wall-clock threshold is ever a gate.
  `PerfBenchmarkTest` is opt-in (`make perf`, or `-Daran.perf=true`, or `RUN_PERF=1
  ./scripts/validate.sh` in either mode) and writes `build/perf/report.{json,md}`.
- **Synthetic data at scale**, generated by DuckDB from `range(N)` with every cell a closed form
  of the row index — so a workload's declared row counts and column statistics are computed from
  the data rather than typed by hand, which is what makes a plan golden at scale mean anything.
- **Two performance findings from the suite.** Planning cost rises with the product of
  join-path depth and union fan-in, and deep enough it exhausts the heap rather than merely
  taking a while. Each enforced denial constraint costs about 2 ms of planning on every query,
  catalog-wide, whether or not the query touches its class.

### Fixed

- The `freyja` component of `/actuator/health` now probes FREYJA's `/healthz` and reports DOWN
  when it answers 503 (join-ranking model not loaded). It probed `/health`, a route FREYJA does not
  serve, and counted the 404 as UP.
- The web client no longer says an agent's read of a virtual product is capped at 1,000 rows. It
  takes the agent's row limit like any other product's.
- `aran-web/e2e/specs/s1-query-stress.spec.ts`'s header claimed the spec had never been executed;
  it ran twice against a live stack on 2026-08-21. Comment only.

## [0.1.0] — unreleased

The first tagged point in Aran's history. It is not a feature release: the work
below makes the repository legally usable and honestly described, which is the
precondition for everything after it. The platform built before versioning
existed is not itemised here.

### Added

- **`LICENSE`** — Apache License 2.0. Until now the repository carried no licence
  at all, which under default copyright law meant no one had the right to use,
  copy, or modify any of it.
- **`NOTICE`** — copyright attribution, and the provenance of the vendored
  constraint-discovery research code (`edu.upc.lima`, `edu.upc.lattice`,
  `edu.upc.data`, `edu.upc.utils`).
- **`SECURITY.md`** — vulnerability reporting via GitHub private advisories with
  an email fallback, response targets the project can actually meet, an explicit
  scope, and a safe-harbour statement.
- **`CHANGELOG.md`** — this file.

### Changed

- **Licence metadata now matches the licence.** `aran-client/pyproject.toml` and
  `aran-lake/pyproject.toml` declared `Proprietary`; `aran-lake/README.md` said
  "Proprietary — UPC Barcelona, DTAK group"; `aran-web/package.json` declared
  nothing. All four now say Apache-2.0.
- **Versions reconciled onto one platform number.** The tree carried four
  unrelated versions (`0.1.0-SNAPSHOT`, `0.0.0`, `0.1.0`, `0.2.0`) and no tags.
  The platform — Java modules, `aran-web`, `aran-lake` — is now `0.1.0`;
  `aran-client` keeps its own lineage. `aran-lake`'s health endpoint reports
  `0.1.0` where it previously reported `0.2.0`; its API history is preserved and
  relabelled in `aran-lake/docs/v0.2-changes.md`.

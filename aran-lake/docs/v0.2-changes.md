# v0.1 → v0.2 changes

> **These version labels are historical and refer to the lake's own API contract,
> not to a platform release.** Neither was ever tagged. Since the versioning
> policy landed, `aran-lake` carries
> the platform version — currently `0.1.0` — because it ships in the same compose
> file and the same release as the backend. This document is kept because it is
> the only record of these breaking changes to the Aran↔lake contract; read it as
> "the second iteration of the lake API", not as a released version.

> **The materialize items below were reverted on 2026-08-27.** `POST
> /api/snapshots/{id}/materialize`, the `snapshot.materialize` job type, its
> handler, `materialize_to_local_parquet` and `test_materialize.py` are all
> deleted — no Aran code path ever called them, and what was left ran caller
> SQL with the `/api/query` safety screen deliberately bypassed. See the note
> at the top of ADR 006. This document is a record of what v0.2 changed, so
> the entries stay as written.

## Breaking changes

* **`dataset_name` removed** from `POST /api/datasets/{id}/snapshots/init`
  and `POST /api/imports` request bodies. The lake no longer carries
  dataset names; Aran owns them (ADR 007).
* **`content_type` is required** on snapshot init. v0.1 defaulted to
  parquet; v0.2 forces an explicit choice so format dispatch works.
* **Profile endpoints removed**: `POST /api/snapshots/{id}/profile`,
  `GET /api/profiles/{id}`, `GET /api/profiles/{id}/blob`. Profile is
  no longer a lake concern (ADR 007).
* **`profile` table removed** from the catalog.
* **`dataset.name` and `dataset.description` removed.**
* **Schema is a clean cut from v0.1.** v0.1 was a scaffold with no
  production data, so v0.2 ships a single migration that bakes in the
  new shape. Existing v0.1 dev installations: drop the database and
  rerun `alembic upgrade head`.

## Additive changes

* **Per-caller auth.** `ARAN_LAKE_SHARED_SECRETS` is a JSON map of
  `{caller_id: secret}`. The legacy `ARAN_LAKE_SHARED_SECRET` form
  still works and is promoted to caller-id `default`. The matched
  caller-id is recorded on snapshots and jobs as `created_by_caller`
  (ADR 005).
* **Format-flexible uploads.** CSV, NDJSON, and Excel (`.xlsx`) join
  parquet as queryable formats. Snapshots carry a `format_options`
  JSONB blob for per-format read hints (delimiter, header, encoding,
  sheet, etc.) (ADR 006).
* **Materialize-as-snapshot.** `POST /api/snapshots/{id}/materialize`
  enqueues a `snapshot.materialize` job that runs SQL against a source
  snapshot and registers the result as a new parquet snapshot.
  Materialized snapshots carry `derived_from_snapshot_id` and
  `derived_via_job_id` for lineage (ADR 006).
* **Raw-bytes download.** `GET /api/snapshots/{id}/download` mints a
  short-lived presigned GET URL for consumers that want to stream the
  bytes directly. TTL is configurable
  (`ARAN_LAKE_DOWNLOAD_PRESIGN_TTL_SECONDS`, default 5 min).
* **Lineage index.** Partial index on `snapshot.derived_from_snapshot_id`
  for cheap "show me everything materialized from snapshot X" lookups.

## Internal refactors

* `Profile` model and all its repository functions removed.
* `upsert_dataset` no longer takes `name` / `description`.
* The DuckDB runner now dispatches on `content_type` to bind the
  source view; the `excel` extension is lazy-loaded on first xlsx use.
* New `materialize_to_local_parquet` helper writes COPY output to a
  local tempfile so we can hash and dedup before uploading.
* New `sha256_of_file` and `upload_file` helpers on the storage adapter.
* `ObjectStore.presign_get` accepts an optional TTL override.

## Configuration changes

| New / changed env var | Purpose | Default |
|---|---|---|
| `ARAN_LAKE_SHARED_SECRETS` (new) | Per-caller secrets, JSON | unset |
| `ARAN_LAKE_SHARED_SECRET` (legacy) | Single secret | unset |
| `ARAN_LAKE_DOWNLOAD_PRESIGN_TTL_SECONDS` (new) | TTL for /download | 300 |
| `ARAN_LAKE_MATERIALIZE_MAX_BYTES` (new) | Cap materialize output size | 10 GiB |
| `ARAN_LAKE_MATERIALIZE_TEMP_DIR` (new) | Scratch dir for materialize | /tmp |

At least one of `SHARED_SECRETS` or `SHARED_SECRET` must be set; startup
fails otherwise.

## Tests added

* `test_auth.py` — multi-secret bearer, legacy promotion, malformed
  inputs.
* `test_format_dispatch.py` — pure-function tests on the format-aware
  reader builder (parquet, CSV/TSV, NDJSON, Excel, escaping, options
  rendering).
* `test_materialize.py` — endpoint contract, payload propagation,
  caller-id audit.
* `test_snapshots.py` — extended with format_options and /download
  coverage.
* `test_jobs.py` — drops dataset_name; adds caller-id propagation check.

## Roadmap (post-v0.2)

* mTLS auth with per-caller certs (defer-from-v0.2; ADR-TBD).
* Streaming an import's parquet directly to S3 (skip the /tmp scratch step)
  for very large outputs.
* `import.from_postgres` real implementation. *(shipped — see the README)*
* Additional ingestion formats (Apache Arrow files, ORC).
* Background sweeper for expired `snapshot_upload` rows.
